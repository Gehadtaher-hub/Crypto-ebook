Overview

Information is a valuable asset used by individuals, universities, hospitals, banks, businesses, and governments. This lecture builds the vocabulary needed to analyze how information can be disclosed, changed, destroyed, or made unavailable.

🔐Protect assets⚠Understand threats🛡️Manage risk

Key points

  • Define information security and explain its importance.
  • Explain CIA and distinguish authentication, authorization, and accountability.
  • Classify threats, vulnerabilities, passive attacks, and active attacks.
  • Distinguish security services from mechanisms.
  • Explain controls, policy, risk, and the network-security model.

Sections 1.1–1.3

Information Security

Information security protects information and information systems from unauthorized access, use, disclosure, modification, destruction, or disruption. The scope is broader than software: people, processes, policies, physical safeguards, hardware, networks, and data all matter.

INFORMATIONPeopleProcessTechnologyPhysical

Key points

  • Digital and non-digital information require protection.
  • Assets include personal, financial, medical, academic, business, government, credential, and key information.
  • Security failures can create legal, financial, operational, and reputational harm.

Section 1.4

CIA Triad

The CIA triad is a compact model for three foundational goals. Confidentiality controls who may see information; integrity protects correctness and authorized change; availability ensures authorized users can obtain information and services when required.

CConfidentialityIIntegrityAAvailabilitySecure Information

Key points

  • Confidentiality controls: encryption, access control, MFA, secure protocols.
  • Integrity controls: MACs, signatures, permissions, versioning, audit logs.
  • Availability controls: redundancy, backup, maintenance, filtering, recovery.
  • One incident may affect more than one property.

Section 1.5

AAA

Authentication verifies an identity claim. Authorization determines which resources and operations the verified identity may use. Accountability makes actions traceable through unique accounts, logs, timestamps, monitoring, and audit trails.

Claim→Authenticate→Authorize→Audit

Key points

  • Authentication asks: Who are you?
  • Authorization asks: What may you do?
  • Accountability asks: Who did what, and when?
  • MFA combines independent categories: know, have, and are.

Section 1.6

Threats, Vulnerabilities, and Attacks

A threat is a potential cause of harm. A vulnerability is an exploitable weakness. An attack is an intentional attempt to exploit a weakness. The impact is the resulting damage; a control reduces likelihood, impact, or both.

Threat→Attack→Vulnerability→Impact

Key points

  • Example threat: cybercriminal.
  • Example vulnerability: weak password.
  • Example attack: password guessing.
  • Example impact: account takeover.
  • Controls: MFA, rate limiting, monitoring, awareness.
Quick check: Write one university-portal example that demonstrates this concept.
Section 1.7

OSI Security Architecture

The OSI Security Architecture organizes communication security into attacks, services, and mechanisms. This prevents a common mistake: naming a technology before clearly stating the protection requirement.

ATTACK→SERVICE→MECHANISM

Key points

  • Attack — What harmful action threatens the system?
  • Service — What protection result is required?
  • Mechanism — How will the service be implemented?
  • Example: message modification → integrity service → MAC or signature.

Section 1.8

Passive Attacks

Passive attacks observe or learn without intentionally changing data or normal operation. Release of message contents exposes information directly. Traffic analysis studies metadata such as source, destination, timing, size, frequency, direction, and duration.

SenderEncrypted traffic ───▶Receiver👁 Silent observer

Key points

  • Passive attacks can be difficult to detect.
  • Prevention is emphasized.
  • Encryption may hide content while communication patterns remain visible.
  • Traffic padding may reduce useful patterns.
Quick check: Write one university-portal example that demonstrates this concept.
Section 1.8

Active Attacks

Active attacks modify, fabricate, replay, impersonate, or disrupt. Security design must combine prevention with detection, containment, and recovery.

🎭Masquerade🔁Replay✏️Modification⛔DoS

Key points

  • Masquerade: pretend to be another entity.
  • Replay: resend an old valid message.
  • Modification: change, insert, delete, reorder, replace, or delay data.
  • DoS/DDoS: consume or disrupt resources to prevent legitimate use.

Section 1.9

Security Services

A security service describes the protection outcome required by a system. Authentication may verify a communicating peer or the origin of a particular data unit.

🪪Authentication🚪Access control🔐Confidentiality✅Integrity✍️Non-repudiation⚡Availability

Key points

  • Authentication
  • Access control
  • Data confidentiality
  • Data integrity
  • Non-repudiation
  • Availability

Section 1.10

Security Mechanisms

A security mechanism is a method used to provide one or more services. A single service often depends on several mechanisms working together.

🧰EncryptionSignatureMACAuditRecovery

Key points

  • Specific: encipherment, signatures, access control, integrity mechanisms, authentication exchange, traffic padding, routing control, notarization.
  • Pervasive: trusted functionality, labels, event detection, audit trail, recovery.
  • A secure website combines certificates, key exchange, authenticated encryption, validation, and logging.

Section 1.11

Network-Security Model

Sender S transforms message M using an algorithm and key information K. Protected X = Tₖ(M) crosses an insecure channel. Receiver R decrypts or verifies it. A trusted third party may distribute keys, issue certificates, validate identity, or timestamp data.

Sender SX = Tₖ(M) ───▶Receiver R⚠ Opponent

Key points

  • Assume an opponent can observe and attack the channel.
  • Readable plaintext is not automatically authentic, fresh, or unmodified.
  • Verify tags, signatures, certificates, keys, and freshness before processing.
  • Reject data when required verification fails.

Section 1.12

Security Controls

Controls are safeguards selected to prevent incidents, discover incidents, or restore secure operation. Defense in depth combines overlapping technical, administrative, and physical controls.

🛡️ Prevent→⚠ Incident→🔎 Detect→🔧 Correct

Key points

  • Preventive: firewall, MFA, encryption, training, locks.
  • Detective: IDS, monitoring, alerts, cameras, audits.
  • Corrective: backups, incident response, recovery, patching, resets.
Quick check: Write one university-portal example that demonstrates this concept.
Section 1.13

Policies and Risk

A security policy defines rules, responsibilities, permitted behavior, and required protection. Risk management identifies assets, threats, and vulnerabilities, estimates likelihood and impact, selects controls, and reviews residual risk.

51015202548121620369121524681012345

Key points

  • Risk = likelihood × impact.
  • Treat risk by avoiding, reducing, transferring, or accepting it.
  • Residual risk remains after controls.
  • Policies should be approved, communicated, enforced, monitored, reviewed, and updated.

Sections 1.14–1.15

Incidents and Activity

Common incident patterns include database leaks, phishing losses, ransomware interruption, DoS outages, insecure applications, and accidental disclosure. Security should be considered throughout planning, development, deployment, operation, maintenance, and retirement.

Asset→Event→Impact→Control
